VL10 Upload

Upload a VL10 extract (.csv or .xlsx). VL10 lists orders before a delivery/Delivery Nbr exists, so rows are matched by Order Nbr instead. Rows with no matching order are created as new orders, using OriginDoc. → Order Nbr, Name 1 → Customer/Supplier, IncoT → Incoterms, ShpCountry → Ship Country, SaTy → Sales Document Type, Open qty → TOT, and Goods Issue → Planned GI Date. If an order already exists for that Order Nbr, this only fills in whichever of those fields are currently blank on it — it never overwrites a value you've already entered.

VL06O Upload

Upload a VL06O extract (.csv or .xlsx). Rows are matched by Delivery against each order's Delivery Nbr. Matched orders get SAP Status set to "GI Complete" when the row has an Actual GI Date, or "Not Yet Shipped" when it doesn't — nothing else on a matched order is touched. Rows with no matching order are created as new orders, using Delivery → Delivery Nbr, Document → Order Nbr, Name of the ship-to party → Customer/Supplier, IncoT → Incoterms, and GI Date → Planned GI Date. Sales Document Type and TOT aren't in a VL06O extract, so those are left blank for you to fill in manually.

PKMS Order Status Upload

Upload a PKMS Order Status export (.csv or .xlsx). Rows are matched by Pickticket Control Number against each order's Delivery Nbr, and PKMS Status is updated to the matching combination (e.g. "70" → "70 Loaded"). This doesn't touch any other field — you can still edit an order's PKMS Status individually any time.

Shiptify Upload

Upload a Shiptify export (.csv or .xlsx). Rows are matched by Slot Name against each order's Order Nbr or Delivery Nbr, and Carrier, Scheduled Pickup Date, and Status are updated. This doesn't touch any other field — you can still edit an order individually any time.
